# Driver attribution contracts

What a driver must establish before it may host cells, per driver. The general obligations are in `10-harness.md` (two-source attribution, S7 wire-first verification, S8 fail-fast liveness, S9 operator legibility) and Q2 in `90-open-questions.md`; this file is the per-driver record of how each driver meets them. A driver absent from this file may run non-gating exploratory cells, but no attribution-dependent conclusion is scored from it.

Evidence discipline: a driver's entry cites either harness-instrument measurements (the standard that settles Q2 for that driver) or attributed external measurements (which specify the driver but do not settle Q2 — the settling run must happen under this harness's own instruments). Every entry is version-pinned; a driver version bump voids the verification until re-measured.

## codex — specified 2026-09-01, not yet implemented; Q2 open pending harness-instrument verification

Source: `codex-driver-handoff.md` (measurements by the uscode-mcp spec session on codex-cli 0.147.0, kept there as its O31–O35, probe recipes included). These are attributed external measurements: they are the basis for the requirements below, and they do NOT settle Q2 for codex — that takes the implemented driver re-demonstrating the effects under this harness's own recording.

Binding requirements for the implemented driver:

1. **API-key credentials only; ChatGPT-login state is refused for attribution cells.** Measured: under ChatGPT login a custom provider still received `web_search` in the tools array, so the noweb mechanism is unproven there; and the credential-isolation measurement (Authorization to a custom provider carries exactly the `env_key` value) means a custom-provider backend cannot ride ChatGPT credentials anyway.
2. **Isolated `CODEX_HOME` per invocation, harness-authored.** Load-bearing for attribution, not hygiene: ambient user config leaked MCP servers and plugin tools into the offered surface, and one ambient server (`node_repl` — arbitrary Node, a network-capable channel) started and ran mid-probe. The codex analogue of the neutral working directory.
3. **Web disable via the noweb custom-provider mechanism, never the config knob.** `tools.web_search=false` was measured dead under both auth modes (web tool live and used, 7–9 invocations, including sandbox-evasion attempts via an r.jina.ai proxy fetch and DNS-over-HTTPS). Mechanism: web-tool registration follows the provider's `supports_standalone_web_search` declaration; builtins declare it immutably, custom providers declare nothing. `wire_api = "responses"` (0.147.0 refuses `"chat"`).
4. **The custom provider IS the harness recorder.** The noweb mechanism and S7's API-boundary capture are the same interposition point: the driver points codex's custom provider at the harness's recording proxy, which forwards to the real backend. One mechanism yields both the web-disable and per-scored-invocation wire verification. Same recording rules as the claude-code recorder: tool names only, never headers (the provider Authorization header carries the real API key), never message content.
5. **Per-invocation effect verification, S7 semantics.** A `web_search` (or any non-MCP network tool) in a wire-captured tools array, or a web-search event in the run record, is an instrument breach: the row is not tool-attributable, the cell is BROKEN. The rationale is the handoff's sharpest exhibit: a present-but-inadequate web tool did not merely leak — it manufactured a fabricated fetch result presented as retrieved (n=1, but the failure class is exactly what attribution cells exist to exclude), so refusal must be hard, not best-effort.
6. **Key injection for spawned MCP servers.** Codex sanitizes the environment of MCP servers it spawns (canary measurement: `PATH`/`HOME` present, parent-env canary absent), so the manifest's `{"$secret": …}` resolution must reach the server by a spawn-helper that injects into process env only — never into the generated codex config (a file artifact) nor `meta.json`'s recorded command. The existing secret-hygiene scan applies to the generated codex config like any artifact.
7. **Native vocabulary, as everywhere**: codex cells carry `reasoning_effort` and friends verbatim; no mapping to Claude's `thinking` exists or is recorded.

Settling Q2 for codex requires, under this harness's instruments: a wire capture across a real cell showing only `mcp__`-namespaced (or codex-equivalent MCP) tools; zero web-search events in the run record; the canary re-run through the spawn helper showing the secret present in the server process env and absent from every artifact; all recorded with the codex version pinned in meta.
