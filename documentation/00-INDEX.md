# Spec index — generic e2e harness for MCP consumers

This directory is the spec for a harness that drives a model consumer against an arbitrary MCP server and records what happened, so that humans and each server project's spec session can score consumer behavior against criteria pinned in advance. The harness ships from this repo as a library/CLI; the server-specific material (manifest, groundings, checks) is a **suite** living in the server's own repo.

## Files

- `10-harness.md` — the verification contract: division of labor, Layers 1 and 2, run mechanics, attribution, cells, grounding rules.
- `20-manifest.md` — the suite manifest schema: the entire interface between a suite and the harness, including generic MCP server registration.
- `30-checks.md` — the declarative Layer-1 check language and its evaluation semantics.
- `40-instruments.md` — the registry of pinned instrument content (crowding procedures, by name/version/content hash); crowded runs are scoreable only against a pin listed there.
- `50-drivers.md` — per-driver attribution contracts: how each driver meets the `10-harness.md` obligations, version-pinned; drivers absent from it host no attribution-dependent scoring.
- `codex-driver-handoff.md` — external measurements from the uscode-mcp spec session (verbatim, provenance for the codex entry in `50-drivers.md`).
- `openrouter-probe-2026-09-18.md` — the spec session's own external probe of the OpenRouter roster (method, served providers, the knob silent-swallow observation); informs Q8 without settling it.
- `90-open-questions.md` — open questions; route answers per `CLAUDE.md`.
- `work-orders/` — numbered work orders from the spec session to the implementation session (started 2026-09-18 at the maintainer's request). Each states deliverables, acceptance as observable artifacts, and what to report; the maintainer may challenge a defective one. A work order is derived from the spec and never overrides it — on conflict the spec files win and the work order is corrected.
- `examples/congressmcp/` — the ancestor suite from congressMCP, kept verbatim as the worked example. Not normative; see its README for what is server-specific and where it deviates from `20-manifest.md`.

## Conventions — these bind

Inherited from the ancestor spec because each was earned by a concrete failure there:

- **Measurement over assertion.** No result stated as fact without a citation to a measurement or an observation recorded in files. A mocked fixture is not evidence.
- **Preregister before a spec change**: expected result and the observation that would falsify it; record the outcome either way.
- **Non-zero denominator.** A claim over a set states the set's size; "all N passed" with N=0 is the vacuous outcome, reported as such (`30-checks.md` builds this into check semantics).
- **A scan that errors must never look like one that found nothing.** Error, fail, vacuous, and pass are four outcomes, not two (`30-checks.md`).
- **Check dead-defensive first.** Before specifying an edge-case contract, confirm the design can reach it.
- **A measurement of a property shares the failure class of its implementation.** An instrument built on the thing it measures cannot clear that thing; hence instrument defects block all other dispositions (`10-harness.md`).
- **Durable state lives in files here, never in conversation.** Rulings, preregistrations, open questions.
- **Commit each ruling as it is made.** This directory's git history is the decision record.

## Settled — do not reopen without new evidence

- **S1 (2026-08-30, maintainer)**: packaging is library/CLI; suites live in server repos. This spec defines the interface contract, not a home for suites.
- **S2 (2026-08-30, maintainer)**: Layer-1 checks are declarative data in the manifest, not code plugins. Pressure valve: an inexpressible contract becomes an open question and a language change, never ad-hoc harness code.
- **S3 (2026-08-30, maintainer)**: the congressMCP material stays as the worked example, verbatim, in `examples/congressmcp/`.
- **S4 (inherited, decided 2026-08-15)**: markdown is one line per paragraph, no hard wrapping — see `CLAUDE.md` for the full rule.
- **S5 (2026-08-30, spec session)**: no warm-by-accident — fresh working directory and fresh server process per cell invocation; carried-in state arrives only via explicit `setup`/`env` (`20-manifest.md`). Rationale: the ancestor's cold/warm cache axis showed state carryover is a cell parameter, so it must be declared, never inherited.
- **S10 (2026-09-02, spec session)**: **self-report is not evidence.** A consumer's own account of its context, tools, or behavior never substitutes for wire or artifact observation — the instrument reporting on itself shares the failure class of what it reports on. Already operative in Q2's instrument ranking (the in-turn probe rejection); numbered 2026-09-02. Provenance correction, same day: E15's "S10" citation referred to the uscde-mcp spec's *own* S10 (which quarantines a model's report about its own context — "cannot distinguish 'one copy was sent' from 'two copies were sent and I did not notice'"), not to a ruling here; this entry was first minted on a misreading of that citation. It stands anyway: the two registers ruled the same principle independently, and the convergence is evidence for the principle, not for the numbering. Any measurement of what reached a model comes from the wire recorder, not from asking the model.
- **S9 (2026-08-31, maintainer + spec session)**: the runner is never silent — progress (cell/prompt, turn transitions, per-cell completion with wall clock and trace-record count) goes to the controlling terminal, and the run directory is named up front. In-flight, hung, and broken must be distinguishable from the terminal. Grounded in DR-1: zero output caused a progressing-but-broken run to be read as hung. Contract text in `10-harness.md` → "Operator legibility".
- **S8 (2026-08-31, spec session)**: instrument liveness is enforced fail-fast at spawn — a SUT that exits or fails to advertise tools before the consumer turn begins BREAKS the cell immediately, without spending the model turn, and the breach is surfaced to the operator live. Grounded in the uscde-mcp first-run incident (`90-open-questions.md` → defect register).
- **S7 (2026-08-31, spec session)**: attribution verification is **wire-first** — tool-surface absence is verified by observation (API-boundary capture per scored invocation where the driver permits interposition; discarded calibration probe per driver version otherwise), never by configuration assertion alone. Grounded in a measurement: a deny-flag left every builtin on the consumer's surface while blocking only invocation (`90-open-questions.md` → Q2, claude-code record). Contract text in `10-harness.md` → attribution.
- **S11 (2026-09-11, maintainer + spec session)**: the driver axis has two families — **product drivers** (third-party consumer harnesses: claude-code, codex), measuring server × shipping product, and the **harness-owned loop driver** (`50-drivers.md` → loop: a minimal agent loop over an OpenAI-compatible endpoint; OpenRouter is one deployment), measuring server × model under a pinned harness scaffold. Cells never pool or substitute across families, in either direction. The spec prescribes no gating tier for either family: this is a public harness whose suites answer to repos the maintainer does not control, so gating is the suite owner's decision, and the harness's obligation is legibility — family, scaffold version, and reproducibility marks in every artifact — never a gating mandate. This supersedes "non-gating by rule" phrasing; the substantive rule that survives is no-substitution, not a gating prohibition.
- **S20 (2026-09-23, maintainer)**: **a slot lost to an exhausted upstream refusal is replaced**, as a whole fresh invocation under S18's attempt counter and budget, with cause `upstream_unavailable` in the attempt record. S18's never-replace rule for every other harness failure stands: the distinction is that a busy provider is not a broken instrument. Answers Q12. Contract text in `10-harness.md` → Layer 2; ordered as WO-12 part B.
- **S19 (2026-09-21, spec session)**: **a crowding procedure pins its mid-task predicate, and the harness checks it from `distractor-state.json` after every pre-turn, on every driver, before sending the scored prompt** — a failing state is precondition unmet (S17), cause `state_mismatch`, replaced under S18, whatever the consumer's exit code or output. Grounded in a scan of 87 live crowded rows: 3 scored floor rows had received the prompt at 1–2 of 4 notes filed, undetected because the precondition was inferred from an exit code; a product driver's empty pre-turn is likewise undetectable today. Predicate for `neutral-file-triage@2` in `40-instruments.md`; contract text in `10-harness.md` → Layer 2; ordered in WO-10.
- **S18 (2026-09-21, maintainer)**: **an invocation that ends precondition unmet (S17) is replaced by a whole fresh invocation, up to three times per slot** — a run parameter, default 3, never in the manifest hash. Replaces only invocations whose scored prompt was never sent: a scored turn's null final or limit is a measurement and is never replaced (S16 stands), nor is any other harness failure. Every attempt is kept and counted; budgets apply. Answers Q11. Contract text in `10-harness.md` → Layer 2; ordered as WO-9 part B.
- **S17 (2026-09-21, spec session)**: **a crowding pre-turn that ends in a consumer outcome leaves the row unscored as *precondition unmet*, with the cause in the row's own record** — the scored prompt is not sent, nothing is retried inside the pre-turn, the row is neither an answer nor a consumer outcome of the scored prompt, and the run manifest counts it apart from `failures`. Dropping such rows cannot bias the rest, by construction: the scored prompt is not in the pre-turn's context. Grounded in one live uscode-mcp floor row whose pre-turn ended on S16's null final after filing one note of four. Contract text in `10-harness.md` → Layer 2; ordered in WO-9; whether the harness makes up the lost repetitions is Q11.
- **S16 (2026-09-21, maintainer)**: **a final message with null content and no tool call is its own recorded outcome** — never written as the text `null`, never hashed, never counted in `answered`. A consumer outcome of S13's family, not a harness failure. Grounded in 7 of 26 rows of a uscode-mcp loop run whose answers were the string `null`. Contract text in `10-harness.md` → Layer 2. **Corollary, same day:** whether the scaffold re-prompts after a malformed or misplaced tool call is tool-loop policy, which is hashed scaffold content; a retry changes what the floor measures, so it can exist only as `loop-scaffold@2`, whose cells never pool with `@1` — never as a patch to `@1` (`40-instruments.md`).
- **S15 (2026-09-21, maintainer)**: **repeats are a run parameter, never manifest content** — `mcp-e2e run --repeats N`. The manifest hash is untouched by N, so comparability across arms and runs is unaffected; a suite states N in its preregistration, where a design parameter belongs. Rejected: a per-cell manifest field (a new hash whenever N changes, for a number that is no part of the instrument) and the status quo (N runs, leaving the in-run distinct-answer count structurally 1). Asked by the uscode-mcp spec session, recorded as Q9. Contract text, including fresh-everything per repetition, repetition as the outer loop, and the layout rule, in `10-harness.md` → run mechanics.
- **S14 (2026-09-18, maintainer + spec session)**: **row measurements are a third artifact class** — mechanical values computed across two artifacts of one row (a trace record and the answer), recorded beside the row with a pinned, hashed method, and never a check outcome or a score. First member: `answer-coverage@1` (`30-checks.md`), wanted by uscde-mcp for the mechanical half of C1 v2's contents clause; the prose half (what the answer *claims*) stays with the scorer. Explicitly not a precedent for Q1: a row measurement asserts nothing and spans no records. Method pinned 2026-09-19 on WO-4's acceptance (`40-instruments.md` pin record), which also corrected five of the spec session's own reference-vector cells — the report's discrepancy was the signal, exactly as the conventions say.
- **S13 (2026-09-18, spec session)**: **answerless turns are classified by cause.** A consumer that runs itself into an endpoint context limit or the scaffold's step cap produced a consumer outcome, scored as a failure to answer; only a broken instrument is a harness failure. Grounded in a live loop row that paged ~1.2MB into context and was refused by the endpoint. Contract text in `10-harness.md` → Layer 2; artifact shape in WO-2.
- **S12 (2026-09-18, spec session)**: **loop-driver eligibility is an endpoint property, never a model-id property.** A model id on a router is served by many endpoints that differ in tool support, quantization, price, and health (measured: 5 of 24 endpoints behind `openai/gpt-oss-120b` did not advertise tools on 2026-09-18 while the model-level flag said they all did), so a (model, provider) pair is what a cell pins, a merge-gating loop cell is pinned, and eligibility is confirmed by a discarded calibration probe per (model, provider, scaffold version, driver version) before any scored turn. Contract text in `50-drivers.md` → loop, requirement 9; probe preregistered as Q8 P-tool-probe. Consistent with S11: gating remains the suite's decision, but a gating cell that is unpinned has no environment identity to attribute to.
- **S6 (2026-08-30, maintainer)**: crowding content is **harness-owned, versioned, and task-shaped** — never suite-authored, never trivia padding. A `crowded` cell selects a named harness crowding procedure; the suite attests the procedure is disjoint from the server's domain, and on collision selects a different harness procedure rather than writing its own. Rationale in `10-harness.md` → "Crowding is part of the instrument"; the padding-vs-task assumption is flagged as measurable in `90-open-questions.md` Q5.
