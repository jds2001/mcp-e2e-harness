# Open questions

- **Q1 — cross-record checks.** The Layer-1 language is per-record (`30-checks.md`). Wait for a real suite contract that needs run-scoped assertions before extending the language; record the contract that forced it.
- **Q2 — driver attribution verification.** Per `10-harness.md`, a driver must verifiably disable non-server network access before hosting attribution cells. The verification procedure is per-driver and empirical (the ancestor's E11 question about Codex web fetching is the template). Needed per driver the implementation supports: the measurement that shows the recorded available-tool surface is trustworthy for that driver. Do not assert; measure and record here.
  Evidence to date (2026-08-31, driver-proof run, `runs/2026-08-31-driver-proof/`): for `claude-code`, the MCP-side surface is now trustworthy by construction — the proxy records advertised vs exposed tools and the isolation cell demonstrated enforcement live (3 advertised, 1 exposed, answer via the one allowed tool). What still rests on assertion: the *built-in* tools (WebSearch, WebFetch, Bash, …) are requested absent via `--disallowed-tools` on the executed argv, but the proxy sees only MCP traffic, so their actual absence from the consumer's surface is a driver claim, not a recorded observation. Q2 stays open on exactly that gap. Instrument candidates, ranked (2026-08-31, after maintainer pushback on the probe idea): (1) **preferred — API-boundary capture**: route the driver's outbound model-API traffic through a transparent recording proxy (claude-code respects `ANTHROPIC_BASE_URL`) and record the actual `tools` array sent on every request — ground truth off the wire, no model mediation, and runnable during scored cells because recording an outgoing request changes nothing in the consumer's context. (2) fallback — a **calibration run**: a separate, discarded invocation with the identical cell configuration whose consumer is asked to enumerate its tools; disclosure-free for scored runs since the scored consumer never sees it, but model-mediated and resting on the assumption that the driver builds the surface deterministically from configuration, so valid only per recorded `cli_version` and re-run on version change. (3) **rejected — an in-scored-turn probe**: breaches no-disclosure (a consumer that has introspected its harness is a different consumer) and verifies an argv assertion with a model assertion, sharing the failure class of what it checks. Required before the first merge-gating attribution cell is scored.
  **claude-code: SETTLED 2026-08-31**, verified by the spec session from artifacts (`runs/2026-08-31-q2-claude-code-probe*`, `runs/2026-08-31-driver-proof/`): (i) the pre-fix calibration probe caught the real defect the ranking predicted — under `--disallowed-tools` alone the consumer enumerated 28 tools including Read/Edit/Write/Glob/Grep/Bash, so the argv assertion was insufficient; (ii) the fix (`--tools ""`, true surface removal, deny-flag kept as belt) re-probed to exactly the three MCP tools; (iii) the preferred instrument now runs on every scored invocation — wire captures across all four driver-proof cells show only `mcp__*` tools in every `tools` array (16 requests), `disallowed_builtins_on_wire: []`, zero forward errors, and the isolation cell's wire union exactly equal to its one exposed tool. Q2 remains open only as the standing requirement for future drivers whose traffic cannot be interposed.
