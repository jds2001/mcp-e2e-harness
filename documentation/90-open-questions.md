## Defect register

- **DR-3 (2026-09-16, instrument defect, harness).** The wire recorder's one allowlisted response scalar — the count-tokens numeric count — is unreadable when the upstream answers brotli-encoded, which is what the driver negotiated in every count-tokens call observed (uscde-mcp C1, floor seq 13 and isolation seq 3: `count_tokens: null`, note "encoding: br"). The recorder decodes gzip and deflate only. It cannot fix this by narrowing the driver's `Accept-Encoding`, because it never modifies traffic; it must decode whatever the driver negotiates. Ruled into the contract (`10-harness.md` → recording contract): scalar extraction decodes the negotiated response encoding, and an encoding it cannot decode is recorded as null plus the encoding named and counted in the digest as an unread scalar — never as no call. Recorded honestly: the current behavior already does the null-plus-note part; the defect is coverage. Implementation to conform; Q7's count half closes on a numeric count from a real run after the fix. **Resolved 2026-09-16:** verified from `runs/2026-09-16-dr3-brotli-verify/` — the same count-tokens request shape (105,242-byte body, brotli response) now yields `count_tokens: 37193`, `count_tokens_unread: 0`; undecodable encodings are counted under `count_tokens_unread`, per the amended contract. Observed on one call (N=1); the brotli path is the one the driver negotiates, so this is the case that mattered.

- **DR-1 (2026-08-31, instrument defect, harness).** First real-suite run (uscde-mcp, `runs/e2e-test-1`, cells floor/A/A1–A3): the SUT died at spawn in every turn (`server_exit: 2` in both proxy metas — the suite's `uv run uscode-mcp` is cwd-dependent and the harness correctly uses a neutral cwd), yet all three cells completed with `harness_failure: null`, `exit_status: 0`, zero trace records, and full model turns spent; the wire capture proves the consumer never had the SUT tools (union = the three distractor tools only). Mechanism reproduced by the spec session from a neutral cwd (`exit=2`). Ruled S8 (fail-fast at spawn); implementation to conform. Note recorded honestly: whether the run-end report would have marked these cells BROKEN was not yet observable (the run was still in progress when diagnosed) — but per S8 the marking must not wait for run end, so the ruling stands either way. Suite-side lesson pushed to `SUITE-AUTHORING.md` (location-independent server commands).

- **DR-2 (2026-08-31, spec defect, schema underspecified).** The harness validator rejected `"watch": null`, failing the first real suite's manifest. `20-manifest.md` never stated whether optional fields are nullable, so the implementation chose strictness in a vacuum — and the resulting validator rejects the spec's own worked example, which carries `"watch": null` on several prompts. Schema text amended in `20-manifest.md`; validator relaxation is implementation conformance work.
