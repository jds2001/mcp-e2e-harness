- **Q8 — loop driver settling measurements (preregistered 2026-09-11).** The `50-drivers.md` → loop entry hosts no scored cells until these run under harness instruments; outcomes recorded here either way, including falsifications.
  - **P-provider-pin.** Expected: with a provider pinned and `require_parameters` set, every request across ≥10 invocations of one cell reports a served provider equal to the pin. Falsifier: any request reporting a different provider, or a response lacking the provider field entirely — an unrecordable identity is a mismatch, not a pass (the scan-that-errors rule). Baseline arm, same cell unpinned: record the served-provider set across the same invocation count. Variation motivates the `reproducibility: unpinned` mark; the mark stands even if this sample happens not to vary, because routing is the router's runtime choice and a quiet sample proves the sample, not the property.
  - **P-knob-drop.** Expected: a request carrying a knob the pinned provider is known not to support is refused or explicitly flagged in the response. Falsifier: success with no indication — the silent swallow. On falsification, loop requirement 5 hardens: knob-dependent conclusions require per-knob, per-provider calibration probes before scoring, and the driver entry is amended to say so.
  - **P-data-policy-routing.** Expected: with `data_collection: "deny"`, every served provider across a multi-invocation run is one OpenRouter's own metadata lists as non-logging. Falsifier: any served provider listed as logging — the preference is then a dead knob of exactly the class the driver file keeps finding, and the disclosure default must move to a hard provider allowlist. Honesty limit restated from the driver entry: this measures routing against OpenRouter's published metadata, never backend behavior, which is unobservable from here.

- **DR-2 (2026-08-31, spec defect, schema underspecified).** The harness validator rejected `"watch": null`, failing the first real suite's manifest. `20-manifest.md` never stated whether optional fields are nullable, so the implementation chose strictness in a vacuum — and the resulting validator rejects the spec's own worked example, which carries `"watch": null` on several prompts. Schema text amended in `20-manifest.md`; validator relaxation is implementation conformance work.
